# A02 – Mala Configuración de Seguridad: Soluciones

## Reto 1 – Configuración expuesta
`GET /a02/config` devuelve `config.util.toObject()`, que incluye el secreto de sesión.

**Corrección:** nunca expongas el objeto de configuración completo. Si necesitas un endpoint
de diagnóstico, filtra explícitamente una lista blanca de claves no sensibles.
```js
router.get('/health', (req, res) => res.json({ env: config.get('env') }));
```

## Reto 2 – Archivo de respaldo expuesto
`GET /a02/backup.cfg` sirve un archivo con credenciales de BD y llaves de terceros.

**Corrección:** los archivos de respaldo/config nunca deben estar dentro del árbol servido
públicamente; deben vivir fuera de `public/` y fuera del control de versiones, gestionados
por un secret manager.

## Reto 3 – Credenciales por defecto
`admin/admin` y `operator/operator123` siguen activas.

**Corrección:** forzar cambio de contraseña en el primer uso, prohibir contraseñas de una
lista de credenciales por defecto conocidas, y aplicar bloqueo tras varios intentos fallidos.

## Reto 4 – Cabeceras verbosas
`curl -I http://localhost:3000/a02/` revela `X-Powered-By`, `X-Debug-Mode` y una cabecera
`Server` falsificada.

**Corrección:**
```js
app.disable('x-powered-by');
// y usar helmet() para fijar cabeceras de seguridad razonables por defecto
```
