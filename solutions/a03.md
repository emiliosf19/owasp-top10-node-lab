# A03 – Fallos en la Cadena de Suministro: Soluciones

## Reto 1 – Dependencia vulnerable
`package.json` fija `js-yaml` en la versión `3.13.0`, que permite construir objetos y
funciones arbitrarias al parsear YAML no confiable.

**Corrección:** actualizar a `js-yaml@^4`, donde `load()` usa por defecto un esquema seguro
que ya no admite los tags `!!js/function` ni `!!js/undefined`. Ejecutar `npm audit` en CI
y bloquear el build ante vulnerabilidades de severidad alta.

## Reto 2 – YAML inseguro
El payload:
```yaml
!!js/function 'function (){ return process.mainModule.require("child_process").execSync("touch /tmp/yaml_pwned") }'
```
enviado a `/a03/parse-config` hace que `yaml.load()` construya una función JavaScript real
a partir del texto. `js-yaml` no la ejecuta por sí solo — pero el controlador del lab, como
haría una app real que trata un valor de configuración como un "hook", sí la invoca
(`parsed()`), lo que dispara la ejecución de código arbitrario en el servidor. Nota:
dentro de la función construida por `new Function(...)` no hay `require` en el ámbito
(corre en ámbito global), por eso el payload usa `process.mainModule.require(...)` — la
misma técnica que usan los exploits reales de esta familia de CVEs (p. ej. CVE-2013-4660).

**Corrección:**
```js
const yaml = require('js-yaml'); // versión >= 4
const result = yaml.load(configText, { schema: yaml.CORE_SCHEMA }); // sin tags de JS
```

## Reto 3 – Plugin sin verificar
`/a03/install-plugin` "instala" cualquier plugin sin comprobar hash ni firma.

**Corrección:** exigir que cada paquete traiga un hash SHA-256 y una firma verificable
contra una llave pública confiable antes de instalarlo; mantener un SBOM (inventario de
dependencias) actualizado.
