# A10 – Manejo Incorrecto de Excepciones: Soluciones

## Reto 1 – Stack trace expuesto
`/a10/calculate-bad` con `b=0` devuelve el `error.stack` completo, incluyendo rutas
absolutas del servidor.

**Corrección:** capturar el tipo de error específico, responder con un mensaje genérico al
cliente y registrar el detalle completo solo en el log del servidor.
```js
try { /* ... */ } catch (e) {
  logger.error(e.stack); // solo servidor
  return res.status(400).json({ error: 'Solicitud inválida.' }); // solo cliente
}
```

## Reto 2 – Path traversal
`/a10/read-bad?file=../config/default.json` navega fuera del directorio `public/` esperado
porque no hay saneamiento de la ruta, y filtra el secreto de sesión de `config/default.json`.
Con suficientes `../` (según qué tan anidada esté tu instalación) también se puede llegar a
archivos del sistema, por ejemplo `/etc/passwd`.

**Corrección:** resolver la ruta con `path.resolve`/`fs.realpathSync` y verificar que el
resultado siga dentro del directorio permitido antes de leer el archivo (ver
`/a10/read-good`).

## Reto 3 – Errores SQL expuestos
`/a10/query-bad?table=nonexistent` devuelve el mensaje textual `no such table: nonexistent`,
revelando el motor de base de datos y su comportamiento interno.

**Corrección:** usar una lista blanca de tablas permitidas y devolver un error genérico
para cualquier valor fuera de esa lista; nunca reenviar el mensaje de error de la base de
datos directamente al cliente.
